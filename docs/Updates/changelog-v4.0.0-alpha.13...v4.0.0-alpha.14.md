## Release notes

### Summary
A protocol-first cleanup release. The bundled osu! ruleset submodule was rebranded from `osu.Game.Rulesets.KeyAsio` to `osu.Game.Rulesets.OverlayAPI`, and the Lazer IPC delta-frame was trimmed down to only the fields KeyASIO actually consumes — score, username, statistics, hit errors, beatmap folder, and the lazer user-data / exe directories are no longer shipped over IPC. Skin loading is now cache-backed and per-client resilient, the audio configuration wizard gained a guided hardware-mode device-routing flow with a live test tone, the "Standard" preset was folded into "Fast", and the first-run wizard is wired back up so new users land in it automatically.


### Features
- **Guided Hardware-Mode Wizard Flow**: `WizardAudioConfigViewModel` introduces three new sub-steps — `ConcurrencyCheck`, `AlternativeDeviceCheck`, and `ProMixRequired` — that walk the user through whether osu! and KeyASIO can share a device, whether another playback device exists, and finally whether to fall back to ProMix. The wizard reuses the new `IWizardTestSoundService` to emit a one-second test snare loop while the user verifies exclusivity, and disables the Software/ProMix card entirely when the `KeyAsio.Plugins.ProMix` plugin is not loaded. (`WizardAudioConfigViewModel.cs`, `WizardTestSoundService.cs`, `WizardAudioConfigView.axaml`, `WizardViewModel.cs`)
- **Persistent Skin List Cache**: New `SkinListCache` serializes the stable and lazer skin lists to `%LOCALAPPDATA%/KeyAsio/skin-lists-v1.json` (versioned, atomic write) so the UI can show skins immediately on startup instead of waiting for directory enumeration or IPC delivery. `SkinManager.LoadSkinsInternal` now publishes cached skins first, then refreshes from disk/IPC. (`SkinListCache.cs`, `SkinManager.cs`)
- **Per-Client Skin Selection Preferences**: `SkinSelectionPreferences` distinguishes user-initiated selection changes from programmatic ones (via `ApplyProgrammaticSelection`), so the cache-fallback no longer overwrites the user's saved skin with `Internal`. Lazer selections are now persisted by synthetic `Folder` (derived from the realm ID) rather than the non-unique skin name. (`SkinSelectionPreferences.cs`, `SkinManager.cs`)

### Enhancements
- **Slimmer Lazer IPC Protocol**: `LazerIpcFrame` and `GameSyncSnapshot` no longer carry `Version`, `Score`, `Username`, `BeatmapFolder`, `Statistics`, `HitErrors`, `UserDataDirectory`, or `ExeDirectory`. Beatmap identity is now `{lazer}` + `BeatmapFilename` resolved through the IPC resource catalog; the lazer exe directory is derived from the running process via `OsuLocator.FindLazerExeDirectoryFromRunningProcess` instead of being sent over IPC. `LazerIpcGameSyncSource.LazerSkinContextReceived` is now a single-arg `LazerSkinInfo[]?` event. (`LazerIpcFrame.cs`, `LazerIpcGameSyncSource.cs`, `SkinManager.cs`)
- **Skin Manager Uses Synthetic Lazer Folders**: `SkinManager` no longer reads the lazer user-data directory or filters out protected skins. User lazer skins get a synthetic `{lazer-skin:ID}` folder with audio resolved through `BeatmapResourceCatalog.FromMappings`; cached skins are merged in when the IPC skin list has not yet arrived. The obsolete `OsuLocator.FindLazerUserDataDirectory` / `ReadLazerCustomStoragePath` helpers were removed. (`SkinManager.cs`, `OsuLocator.cs`)
- **Preset Simplification**: The `Standard` preset was removed. `Fast` now maps to `Peak` + `ProMixFocus` (previously the Standard config) and its description was rewritten to "standard resource usage to deliver the best listening experience"; `Extreme` is unchanged. The preset dialog grid was reduced from three columns to two. (`PresetManager.cs`, `PresetSelectionDialog.axaml`, `SR.resx`, `SR.en.resx`, `SR.zh-hans.resx`, `SR.ja.resx`)
- **Theme-Aware Red Accent**: `MainWindow.UpdateRedTheme` now picks distinct dark/light `SukiColorTheme` variants for the exclusive-device Red indicator instead of a single flat color. (`MainWindow.axaml.cs`)
- **First-Run Wizard Restored**: The commented-out `RequestShowWizard` hookup and `IsFirstRun` auto-launch were re-enabled in `MainWindow`; the dialog width was tightened from 760 to 660. (`MainWindow.axaml.cs`, `WizardDialogView.axaml`)
- **Settings Page Reorganization**: The preset group box now hosts the wizard entry alongside preset selection, and the duplicate wizard `SettingItem` further down the page was commented out. A new `Wizard_SubTitle` localization string ("只需几个步骤，即可完成 KeyASIO 配置。" / "Configure KeyASIO in just a few steps.") was added across all four cultures. (`SettingsPage.axaml`, `SR.resx`, `SR.en.resx`, `SR.zh-hans.resx`, `SR.ja.resx`)
- **AsioToAudioConverter**: New `IValueConverter` that rewrites the literal `ASIO` substring to `Audio` for display, used by the hardware concurrency-check step to render the selected device name. (`AsioToAudioConverter.cs`, `WizardAudioConfigView.axaml`)

### Fixes
- **Lazer Combo-Break SFX Logic**: `PlayingState` now uses a unified `ShouldPlayComboBreak` helper. Lazer triggers the combo-break sample when `newCombo == 0 && oldCombo > 20` (independent of score, since lazer no longer sends it), while stable preserves the existing score-guarded decrease-based condition. The fragile `_lastObservedLazerMissCount` / `ConsumeLazerMissIncrease` heuristic was removed. (`PlayingState.cs`)

### Miscellaneous
- **Submodule Rebrand**: `dependencies/osu.Game.Rulesets.KeyAsio` was replaced by `dependencies/osu.Game.Rulesets.OverlayAPI` (commit `731aa9f`); `KeyAsio.Sync` and `KeyAsio.Application` now reference `OverlayAPI.LazerProtocol` instead of `KeyAsio.LazerProtocol`. (`.gitmodules`, `KeyAsio.Sync.csproj`, `SkinManager.cs`, `LazerIpcFrame.cs`, `LazerIpcGameSyncSource.cs`)
- **Test Internals Exposure**: `KeyAsio.Sync` now declares `[InternalsVisibleTo("KeyAsio.UnitTests")]` so the slimmed-down protocol and state logic can be unit-tested. (`AssemblyInfo.cs`)
- **New & Expanded Tests**: `AsioToAudioConverterTests`, `PlayingStateTests` (stable vs lazer combo-break matrix), `PresetManagerTests`, `SkinListCacheTests`, `SkinSelectionPreferencesTests`, and `WizardAudioConfigViewModelTests` were added; `LazerProtocolTests` gained assertions that the protocol exposes only the required `LazerFieldKind` set and a minimal `LazerSkinInfo` round-trip. (`tests/KeyAsio.UnitTests/*`)
